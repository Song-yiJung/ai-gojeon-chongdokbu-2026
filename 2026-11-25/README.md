# 3회 — TEI 기반 인코딩과 프롬프트 반자동화

2026년 11월 25일

각자 고른 일제강점기 사료를 TEI 기반 XML로 만든다. 다만 LLM이 한 번에 만들어 준 것을
받아 쓰지 않는다. **프롬프트를 네 단계로 고쳐 가며 결과가 어떻게 달라지는지 직접
확인한다.**

1회와 2회는 공통 자료를 다 같이 다루었다. 이 회차부터는 각자 자기 자료로 간다.

## 프롬프트 네 버전

| | 프롬프트에 들어가는 것 | 판단하는 쪽 |
|---|---|---|
| 1 | 아무 기준 없음 — 「이 텍스트를 XML로 변환해」 | 기계 |
| 2 | TEI 지정 + 문서의 성격 한 문장 | 기계 |
| 3 | 원문 보존 + 태그 대신 제안, 근거 제시 | **사람** |
| 4 | 변환의 목적과 역할 지정 | 사람이 질문을 정하고 기계가 맞춤 |

**3번이 전환점이다.** 여기서 LLM이 「태깅하는 자」에서 「제안하는 자」로 바뀐다. 자동화는
기계가 끝까지 하는 것이고, 반자동화는 기계가 후보를 내고 사람이 고르는 것이다.

3번에서 고른 요소 목록이 그대로 4번 프롬프트의 입력이 된다. 그래서 3번은 XML을 만들지
않는다.

4번에서는 같은 원문이라도 목적이 다르면 불러야 할 TEI 요소가 달라진다는 것을 본다.
사료 판독이 목적이면 인명·기관·날짜·판독 불확실 쪽이고, 서지학적 판본 비교가 목적이면
이본·독법 쪽이다. 2회의 「무엇을 데이터로 남길 것인가」가 여기서 「무엇을 묻느냐에 따라
남길 것이 달라진다」로 한 단계 올라간다.

## 결과를 무엇으로 재는가

정답 TEI 문서가 없으므로 사람이 눈으로 판단할 수밖에 없는 것이 많다. 대신 **기계가 대신
확인해 줄 수 있는 것이 셋 있다.** 이것이 이 수업의 평가 지표다.

1. **원문 변형** — 태그를 벗겨 원문과 맞춰 본다. 旧字體가 신자체로 바뀌거나 연호가
   서기로 바뀌는 일이 흔하다.
2. **well-formed** — 파일을 브라우저에 끌어다 놓으면 바로 알 수 있다.
3. **비-TEI 요소** — TEI에 없는 요소를 모델이 지어내는 일이 있다.

3번 버전에는 하나가 더 붙는다. **제안 이유로 댄 TEI Guidelines 절 번호가 실제로
있는지**다. 요소 이름은 대체로 맞지만 절 번호와 인용 문구는 자주 틀린다. 공식 문서에서
직접 찾아 확인한다.

## 파일

| 파일 | 무엇인가 |
|---|---|
| `프롬프트작성지침_한국어본.docx` | 공식 문서 두 편의 한국어본. 네 버전이 각각 어느 항목에서 나왔는지 표시했다 |
| `프롬프트실습_기록표.xlsx` | 공유 스프레드시트 양식. 시트 둘 — 원자료, 프롬프트기록 |
| `참고문헌.md` | 이 회차의 근거가 된 연구와 문서 |

## 기록표 쓰는 법

- **시트 1 「원자료」** — 수업 전에 채운다. 각자 자기 번호 행에만 쓴다. 「한 문장 규정」
  칸에 쓴 문장이 그대로 2~4버전 프롬프트에 들어간다.
- **시트 2 「프롬프트기록」** — 사람당 네 행. 「왜 바꿨나」 칸이 비면 프롬프트 모음일 뿐
  기록이 아니다.
- 긴 텍스트를 셀에 그냥 `Ctrl+V` 하면 줄바꿈 기준으로 여러 셀에 흩어진다. 셀을
  더블클릭해 편집 상태로 만든 뒤 붙여넣거나 `Ctrl+Shift+V`를 쓴다.

## 지킬 순서

1. 고치기 전에 무엇을 볼지 정한다. 검사 세 가지.
2. 한 번에 한 군데만 고친다. 두 군데를 동시에 바꾸면 무엇 때문에 달라졌는지 알 수 없다.
3. 고친 뒤 같은 검사를 다시 한다.
4. 무엇을 왜 바꿨는지 적는다.
